## 写在前面

国内用户想稳定使用先进 AI API 并不容易。

官方渠道有门槛，第三方中转站数量又很多：有些站点价格漂亮但质量波动大，有些模型名称写得很满但实际返回不一定干净，还有一些接口不是一直掺水，而是高峰期、低余额、特定模型、特定时间段才出现异常。

所以，选中转站不能只看宣传页，也不能只跑一次简单问答。

智知 AI 做的是一件更朴素但更有用的事：把中转站接口放进检测流程里，持续观察它到底像不像目标模型、稳不稳定、有没有间歇性异常，然后把结果整理成普通用户也能看懂的收录与对比。

## 我们关注什么

一个中转站是否值得长期使用，主要看四件事：

1. **模型纯度**：标的是 Claude / GPT / Gemini，实际返回是否符合目标模型特征。
2. **接口稳定性**：不是偶尔能跑，而是在不同时段、不同任务下持续可用。
3. **价格与风险**：便宜不是问题，但异常低价往往需要解释。
4. **长期体验**：文档、客服、充值门槛、故障通知、账单透明度都会影响真实使用。

我们不会把一次检测包装成绝对结论。中转站行业变化很快，真正有参考价值的是持续观察、横向对比和异常记录。

## 检测维度

智知 AI 的检测不是简单问一句“你是谁”。我们会结合多个维度看接口表现：

| 维度 | 我们会看什么 | 主要识别的问题 |
| --- | --- | --- |
| 协议响应 | 返回结构、错误格式、流式表现、上下文字段 | 伪装接口、兼容性异常 |
| 身份一致性 | 模型自述、能力边界、拒答风格 | 低价模型冒充高价模型 |
| 知识边界 | 时间线、已知盲区、常识密度 | 模型族错配、能力降级 |
| 响应指纹 | 输出节奏、格式习惯、长文本稳定性 | 二次加工、代理层替换 |
| 推理表现 | 代码、复杂任务、多轮上下文 | 高压任务下的真实能力 |
| 心跳检测 | 多次定时与不规则探测 | 间歇掺水、时段性不稳定 |

## 为什么要做收录

中转站信息更新非常快。

今天价格合适，不代表下周还是同一条渠道；今天单次检测通过，也不代表高峰期不会切线路；一个站点的首页说支持某个模型，也不代表所有分组、所有 Key、所有时段都一样。

收录的意义不是替任何站点背书，而是把可观察的信息放在一起，方便用户在选择前先做基础判断：

- **纯度分**：目标模型匹配度与异常特征综合判断。
- **掺水风险**：是否出现模型替换、能力降级、响应异常。
- **在线率**：接口是否持续可达，是否频繁失败。
- **延迟表现**：请求响应是否稳定，波动是否过大。
- **价格信息**：尽量记录公开价格、常见渠道和最低充值门槛。
- **人工补充**：把自动检测不容易表达的体验写清楚。

## 单次检测与心跳检测

单次检测适合快速判断一个接口有没有明显问题。

但很多中转站的问题不是“永远掺水”，而是“间歇掺水”：平时看起来正常，一到高峰期、低价渠道、特定模型或连续调用时就出现异常。

所以我们提供心跳检测思路：在一段时间内做多次定时和不规则探测，记录分数走势、失败节点、延迟波动和异常时间。对于写代码、跑 Agent、自动化任务、长文本生成这类长期工作流，心跳结果通常比单次结果更有参考价值。

## 适合谁看

- 正在挑选 Claude / GPT / Gemini 中转站的用户。
- 用 API 写代码、跑 Agent、做自动化任务的开发者。
- 对模型真实性、价格透明度、稳定性比较敏感的人。
- 不想只靠广告、群友口碑或站点自述做判断的人。
- 已经在用某个中转站，但想知道它有没有间歇异常的人。

如果你只是偶尔体验一次模型，随便找个低额试用也许够用；如果你要长期把 API 接进工作流，建议先检测、少量充值、保留备用渠道。

## 使用建议

1. 新站点先小额测试，不要一次性大额充值。
2. 先测你真正要用的模型，不要只看模型列表。
3. 不要只看一次结果，最好观察多个时段。
4. 价格异常便宜时，要特别关注是否存在低价模型替换。
5. 编程、长文本、工具调用任务更容易暴露模型差异。
6. 关键业务不要只依赖单一中转站。
